# Визитка Платформы АРХИ

Публичная одностраничная визитка изделия «Платформа АРХИ, компактная
редакция» (ТЗ 11710-11710). Показывает, что изделие делает, как выглядит
и что даёт, и **собирает заявки на показ и на дистрибутив** — письмом
на почту владельца.

Само изделие живёт в `~/ARCHI-NSU` и работает локально. Визитка — отдельный
проект намеренно: у неё другая задача, другой читатель и другой срок жизни.

---

## Зачем она заведена

Изделие локальное: показать его команде НГУ или Айбим удалённо было нечем.
Ссылка решает это, но ставит второй вопрос — **кому уходит дистрибутив**.
Архив несёт исходный текст и документацию целиком, поэтому ссылки
на скачивание здесь нет: есть заявка, а решение принимает человек.

## Что внутри

| Файл | Что это |
|---|---|
| `index.html` | сама визитка: герой, что даёт, как выглядит, девять требований, эффект, состав поставки, как связаться |
| `404.html` | «такого адреса нет»; Vercel отдаёт её со статусом 404 сам, настройки не требует |
| `style.css` | **копия** файла стилей изделия. Не править: затрётся при переносе |
| `public.css` | всё, что нужно визитке сверх изделия: блок «связаться», снимки, состав |
| `public.js` | шапка при прокрутке. Больше ничего |
| `vercel.json` | заголовки и `trailingSlash: false` |
| `img/` | то, что отдаётся людям: снимки ужаты до 1600 px по ширине |
| `ishodniki-kartinok/` | исходные снимки экрана. Наверх не уезжают (`.vercelignore`) |
| `favicon.svg` / `favicon.ico` | значок. SVG читают браузеры, ICO просят мессенджеры — напрямую по `/favicon.ico`, не заглядывая в разметку |

**Этот файл наверх не уезжает.** `.vercelignore` отсекает все `*.md`, и README
в том числе. Приватность репозитория тут ни при чём: репозиторий приватный,
а деплой публичный, и файл отдавался бы по `/README.md` кому угодно — вместе
с порядком публикации и оценкой прав на чужие данные. Читали бы его ровно
те, про кого он написан.

## Публикация на Vercel

### 1. Репозиторий

```bash
cd ~/ARCHI-NSU-Public
git init && git add . && git commit -m "визитка АРХИ"
gh repo create ARCHI-NSU-Public --private --source=. --push
```

### 2. Проект в Vercel

**Add New Project → Import Git Repository →** `ARCHI-NSU-Public`.
**Framework Preset: Other.** Больше ничего задавать не нужно: ни команды
сборки, ни каталога вывода, ни переменных окружения. Импорт — и опубликовано.

**Настраивать нечего намеренно.** До 13.09.2026 на сайте стояла форма
заявки: серверная функция `api/zayavka.js`, ключ к почтовой службе Resend
и три переменные окружения, которые надо было завести до первого деплоя
и не забыть продлить. Всё это обслуживало посредника между человеком
и почтовым ящиком, в который письмо и так приходило. Посредник снят, адрес
написан на странице открыто. Цена известна и принята: открытый адрес
собирают рассыльщики.

Отсюда следствие, которое стоит помнить при правках: **`api/` в этом
проекте нет и заводить его не надо.** Появится — вернутся и переменные
окружения, и разговор про 152-ФЗ, и вопрос, кто чистит накопленное.

### 3. Если адрес вышел не `arhi-nsu.vercel.app`

Адрес прописан в трёх местах: `canonical` и `og:` в `index.html`,
`sitemap.xml` и `robots.txt`. Поменять одной командой:

```bash
STARYY=arhi-nsu.vercel.app
NOVYY=<как назвали проект>.vercel.app
grep -rl "$STARYY" index.html sitemap.xml robots.txt \
  | xargs sed -i '' "s|$STARYY|$NOVYY|g"
```

Пока адрес не совпадает, ломается не сайт, а две вещи: карточка при
пересылке ссылки в мессенджер и то, как страницу видит поиск.

## Проверка после публикации

Проверяется **обе стороны**: и что нужное отвечает, и что лишнее не отвечает.
Половина проверки ловит половину бед.

```bash
S=https://arhi-nsu.vercel.app

# 1. Живые адреса обязаны отдавать 200
for p in / /style.css /public.css /public.js \
         /favicon.svg /favicon.ico /img/chat-svodka.jpg; do
  printf "%-28s %s\n" "$p" "$(curl -s -o /dev/null -w '%{http_code}' "$S$p")"
done

# 2. Несуществующее обязано отдавать 404, а не главную страницу.
#    /README.md здесь не для полноты: он лежит в репозитории рядом
#    и попал бы наверх, забудь мы про .vercelignore.
for p in /net-takoy-stranicy /wp-login.php /politika.html /README.md; do
  printf "%-28s %s\n" "$p" "$(curl -s -o /dev/null -w '%{http_code}' "$S$p")"
done

# 3. Доехал ли vercel.json — по заголовку, которого без него не бывает
curl -sI "$S/" | grep -i x-vizitka          # ждём: x-vizitka: arhi

# 4. Косая черта на конце обязана переадресовывать, а не давать 404
curl -s -o /dev/null -w '%{http_code}\n' "$S/404.html/"        # ждём 308

# 5. Серверных путей нет вовсе — бывшая функция обязана отдавать 404
curl -s -o /dev/null -w '%{http_code}\n' "$S/api/zayavka"      # ждём 404

# 6. Почта на месте и написана целиком: это единственный способ связаться,
#    и опечатка в ней стоит всех заявок разом
curl -s "$S/" | grep -o 'banksnab@gmail\.com' | head -1
```

**Про открытый адрес.** Он написан на странице буквами, и это решение,
а не недосмотр: рассыльщики такие адреса собирают. Взамен ушли серверная
функция, ключ к почтовой службе, три переменные окружения и согласие
по 152-ФЗ — всё ради посредника перед тем же почтовым ящиком. Начнёт
приходить спам — заводится фильтр в почте, а не форма на сайте.

**Почему здесь нет сплошной переадресации `/(.*) → /index.html`.** Это
канонический рецепт для одностраничных приложений, и он же делает сайт
мягким 404: любой несуществующий адрес отвечает 200 и показывает главную,
а поиск считает такую страницу существующей. Здесь сайт статический,
файлы лежат на диске, и переадресация не нужна вовсе
(урок `vercel-cleanurls-breaks-spa-rewrite.md` и `spa-catchall-rewrite-is-a-soft-404.md`).

**`cleanUrls` не включать.** С ним `/index.html` перестаёт отдавать файл
и начинает переадресовывать, а это ломает и переадресацию, и проверки выше.

## Перенос правок из изделия

Оформление визитки — копия оформления изделия. Чтобы правки доезжали:

```bash
./obnovit-iz-izdeliya.sh
```

Скрипт переносит `style.css`, значок и картинки. **`index.html` он не
трогает**: у визитки своя шапка, свои разделы и свой блок «связаться»,
и слепой перенос затёр бы их. Текст, изменившийся в изделии, переносится руками —
и это осознанная цена, а не недоделка.

## Что на визитке не показывается и почему

* **Рабочие страницы изделия** — стройпортфель, регламенты, администратор.
  Их нет на этом домене, и ссылки на них вели бы в никуда.
* **Названия объектов заказчика.** На снимках их нет ни одного: экран
  регламентов имён не показывает, а из чата взяты сводка, состояние
  и ответ на свободный текст. Это данные Группы МЕТА и Айбим, и права
  публиковать их у нас нет.
* **Ссылка на архив.** Дистрибутив уходит по заявке, а не кнопкой.
